# ObserverLoop Protocol

The wire contract for ObserverLoop: the signed envelope, the event registry, the
NATS subject grammar, the JetStream topology, and the JSON Schema payload set.

This repository is Apache-2.0 so that any consumer can depend on it. It contains
no orchestration logic and imports nothing from `ObserverLoop/conductor`.

> **Project status:** MVP. Go binding only. The TypeScript binding described in
> the implementation plan is not built yet — there is no SaaS consumer.

## What is here

| Path                       | Hand-written | Description                                        |
| -------------------------- | ------------ | -------------------------------------------------- |
| `registry.yaml`            | **yes**      | The only enumeration of event types. Everything else derives from it. |
| `registry.schema.json`     | **yes**      | JSON Schema for `registry.yaml`.                   |
| `schemas/envelope.json`    | **yes**      | The signed envelope.                               |
| `schemas/payload/*.json`   | **yes**      | One schema per registry entry.                     |
| `fixtures/valid/*.json`    | **yes**      | Envelopes that must validate.                      |
| `fixtures/invalid/*.json`  | **yes**      | Envelopes that must fail, each with a reason.      |
| `go/protocol/*_gen.go`     | no           | Generated by `protoc-registry` from the registry.  |
| `go/protocol/schemas/`     | no           | Verbatim copy of `schemas/`, so `embed.FS` can reach it. |
| `fixtures/manifest.json`   | no           | Generated coverage manifest.                       |
| `fixtures/signing/*.json`  | no           | Generated Ed25519 conformance vectors.             |

Generated files carry `// Code generated by protoc-registry. DO NOT EDIT.` (or,
for JSON, are listed above) and are committed. `make generate` followed by
`git diff --exit-code` is the drift gate.

## Go module

```
go get github.com/ObserverLoop/protocol/go@v0.0.3
```

The module lives in the `go/` subdirectory. Import path:
`github.com/ObserverLoop/protocol/go/protocol`.

## Adding an event type

1. Add one entry to `registry.yaml`.
2. Add one schema at `schemas/payload/<type>.json`.
3. Add at least one fixture at `fixtures/valid/<type>.json`.
4. Run `make generate && make check`.

Nothing else is hand-edited. The conformance runner fails if a registry entry
has no schema or no fixture.

## Invariants the test suite enforces

- `ParseIdentifier` is the only identifier validator, and the only regular
  expression in the Go tree.
- `SubjectFor` errors rather than truncating: empty required token, or a subject
  over 255 bytes.
- `ParseSubject` round-trips `SubjectFor` for every event type.
- `SigningBytes` is the RFC 8785 canonical form with `signature` omitted.
- No payload schema declares a `reasoning`, `thinking`, or `chain_of_thought`
  property, at any depth.
- `tool.call` carries no tool arguments and `tool.result` carries no tool
  output. Both bind to the local raw capture by digest instead; the payload
  roots are closed, so a publisher cannot add them.
- An unknown protocol MAJOR is rejected; an unknown MINOR is accepted.

## Development

```
make generate   # regenerate everything derived from registry.yaml
make test       # go test ./...
make lint       # pinned golangci-lint
make check      # build, vet, lint, test -race, and the generation drift gate
```

## Conformance fixtures

`fixtures/manifest.json` indexes every event type, its schema, and the fixtures
that cover it; the generator fails if a registry entry has no fixture.

`fixtures/signing/` carries cross-language Ed25519 vectors. Each vector gives
the envelope, the RFC 8785 canonical form with `signature` omitted (base64 and
SHA-256), and the signature over exactly those bytes. The key is derived from a
fixed input and Ed25519 signing is deterministic, so the vectors regenerate
byte-identically. The key is a conformance key; it signs nothing outside this
repository.

To verify a vector in another language: base64-decode `canonical_base64`, check
its SHA-256 against `canonical_sha256`, and verify `signature` over those bytes
with `public_key_base64url` from `fixtures/signing/key.json`. Independently,
canonicalise the vector's `envelope` with `signature` removed and confirm you
reproduce the same bytes.
